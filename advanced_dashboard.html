Secure the original firmware

vault not loaded
The ESP32 bridge only forwards UART, and the ADT6101P bootloader is receive-only: no command reads the flash back, and the vendor OTA tool has no dump function. A byte-for-byte chip dump still needs SWD. What runs automatically instead: the console identifies the connected radar's version, imports the legally obtained original image from firmware_in/, verifies its SHA-256 and stores a safeguard receipt. You can also import an image manually below.
Watches firmware_in/ and imports every complete full image automatically. After the radar reports its version (0xFFFF), the console matches it to a verified local original and writes firmware_vault/safeguard.json. This confirms a version match — it does not read the chip.
Not scanned yet.
Accepted: full OTA image (16-byte header + app, flashable and buildable), app-only image, or a raw SWD dump (backup only). Stored copies are immutable and SHA-256 is checked on import. Everything stays local; nothing is uploaded.

Upload / flash the image

manual · two-step confirmation
The dashboard never flashes. Download the generated full image, open the Web Flasher, connect the XIAO over USB and select the file. The flasher validates the header and SHA-256, shows the target and only sends data after an explicit confirmation.
Open Web Flasher
Flashing uses TinyFrame 0x3000 → XMODEM-CRC 128-byte blocks → EOT. A failed update can leave the radar in the bootloader, so keep the original image at hand.
